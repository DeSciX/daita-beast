# join — the one way in, every session; seating sets the root

A seat is created once with `/daita-beast:seat` (`seat.sh new`), which also makes its home. A session takes it from wherever the session started: every session starts in the folder the window was launched in (the launch folder), and any number of seats share that launch folder or window. The session holds no seat until the person names one (or it was told its seat).

1. Call `ListAgents`; its first line names this session (`This session is <name> [<ref>]`).
2. From any directory:
   ```
   ${CLAUDE_PLUGIN_ROOT}/scripts/join.sh <SEAT> --address "<name> [<ref>]" [--agent <name>] [--workstream <slug>]
   ```
   `<SEAT>` is a LABEL, `login/LABEL` or the identity `slug/LABEL/login`. `--agent` only when the role changed (the agent file must exist); `--workstream` only when the seat moves to another workstream. Its first line is `SEATED <id> at <home>`, then `role: <agent> at <path>`. `--address` records the session's address as the seat's `BEAST-ADDRESS` comment on its tracking issue (and the machine-local cache); do it at every join, the address changes on every reload.
3. **From now on the seat's root is `<home>`.** The shell returns to the launch folder after every command, so every shell command starts with `cd <home> &&` or uses `git -C <home>` and absolute paths; every file edit uses an absolute path under `<home>`. Read `<home>/CLAUDE.md` now (join's last section names it; it does not load by itself when the session started elsewhere) and again after any compaction.
4. Act on what it prints: commit `.beast/roster.json` (in the main checkout) and the CLAUDE.md when they changed; delete or trim each memory file it lists (working state is the handoff on your tracking issue, durable seat facts are your notes, `notes.sh`, the rules are the CLAUDE.md block and your role is the agent file join named; the launch folder's auto-memory is shared by every seat started there, so it keeps only short pointers and lessons true for all of them) and fix `MEMORY.md`'s index; then work the inbox it printed. A long inbox or memory list: hire the `seat-clerk` agent, which drafts acks, the handoff and the triage, and posts nothing.

Join finds the seat through the checkouts this machine can name: the launch folder's own checkout, the folders of every VS Code workspace file (walking up from the launch folder to `$HOME`) that lists the launch folder in any position, and the machine index `~/.beast/checkouts.json` (written by `seat.sh new`, `bootstrap.sh` and every join). The seat's row is the one in the roster of the checkout of its own repo. It refuses only when the seat has no home on this machine, naming the clone and `seat.sh new` steps (a missing home of a rostered seat is re-created by `seat.sh new <SEAT> --repo-path <checkout>`), a bare label that names several seats (name it `login/LABEL`, or `slug/LABEL/login` when the same login and label sit in two workstreams), and a home whose `.beast/seat.json` names another seat: two seats never share a home. The Beast block goes into the home's CLAUDE.md: the repo's for a checkout or worktree home, the wrapper's own for a wrapper, the subdir's own for a subdir (never the checkout root's). It is generated from `templates/claude-block.md`: never edit it by hand, the next join undoes it. A roster row without a `home` is read as a checkout home, and join tells you once to record it with `seat.sh new <SEAT> --kind checkout`. A row carrying `role` or `tracking`, or without `agent` or `workstream`, is refused naming the key: the role is an agent file and the tracking issue is found by the workstream's labels.

Without a shell (Cowork, claude.ai), use the `connector` skill: its recipe of the same name, or its list of the acts it cannot do.
