Token rewards for contributors

How an open-source contribution becomes a recorded award in a DeSciX community's token: bounty, pull request, award, monthly ledger. All of it happens on the public repo, which serves as the bulletin board. As built in daita-beast 1.5.11, checked against the scripts on 2026-10-20. At 21:28 UTC that day the marketplace DeSciX/DAITA pinned daita-beast ref "1.5.10", tag 1.5.10 of DeSciX/daita-beast, so a marketplace install was 1.5.10 at that time.

In short
  • An award is a GitHub comment plus a label. A repo admin or maintainer posts one comment of a fixed shape, BEAST-AWARD amount=… token=… to=@… for="…", and adds the label awarded. Nothing else records it.
  • Only a repo admin or maintainer can award. The script refuses anyone else. The monthly ledger also drops, loudly, any award comment whose author lacks that role.
  • The token is the community's, and the community decides who awards it. For egpt-frqtl and egpt-godsworld that is EGPT, held by the community repo DeSciX/EGPT. That repo's .beast/awarders.json lists the repos that may award EGPT, and the ledger is committed there. A sub-app has no token of its own.
  • An award is paid as a DeSciX offer. The monthly ledger also emits the sheet the DeSciX platform's Offers import reads (From ledger to offer). Nothing in Beast touches a blockchain or a wallet.
  • Whose GitHub identity and quota each call uses is covered in Beast messaging paths.

1. The path

Bounty issue
label bounty→ Your PR
Closes #n or Bounty #n→ Merge (or decline)
by a maintainer, in GitHub→ Award
BEAST-AWARD + awarded→ Monthly ledger
awards/YYYY-MM.jsonl + .md

A bounty is optional. A merged PR without a bounty, a review that led to a change, or a good-effort submission that was declined can all be awarded at the owner's discretion, as the repo's award policy says.

2. For contributors: how to earn and how to submit

  1. Find a bounty. Open issues labelled bounty on the public repo, for example https://github.com/DeSciX/egpt-frqtl/issues?q=is%3Aopen+label%3Abounty. The issue's ## Bounty section gives the amount. That amount is a floor, not a cap.
  2. Submit a pull request on that repo, one submission per PR, with Closes #<n> or Bounty #<n> in the description. You need no Beast install, no seat and no DeSciX account to submit.
  3. Wait for the maintainer's decision. If accepted, the PR is merged and you receive the award. A declined PR is closed and may still receive an effort award.
  4. The award arrives as a comment. GitHub notifies you, because the comment mentions @<your login>. Only a comment from a repo admin or maintainer counts. Anyone else can post the same text, but it is dropped from the ledger.
  5. Check the ledger. Each month the community owner commits awards/<YYYY-MM>.md to the community repo (for EGPT: DeSciX/EGPT). It lists totals per login and every award.

You do nothing else to "submit for rewards". Your GitHub login is the key. Linking that login to a wallet is a DeSciX claim flow outside Beast, and it does not exist yet (Gap 4).

3. For maintainers: posting bounties, awarding, building the ledger

The award policy (once per repo)

bounty.sh and award.sh read .beast/award-policy.md from the checkout you run them in. They refuse to run unless the file meets four conditions:

  • Its first line names the repo you are awarding on.
  • It has a Token: line, and that token matches the one you pass.
  • It has a Community: <owner/repo> line naming the repo that holds the token's community.
  • It contains no unfilled field.

For DeSciX/egpt-frqtl the first lines are:

# Award policy — DeSciX/egpt-frqtl

Token: EGPT (conceptual units until the DeSciX DIP import exists).
Community: DeSciX/EGPT (the repo that holds the EGPT community: its `.beast/awarders.json` lists the repos that may award EGPT; a repo it does not list awards nothing).

DIP is Digital IP Points, DeSciX's points for contributions that others use, which convert to community-token rewards in airdrops. "The DIP import" is DeSciX reading the ledger's .jsonl into those points; it does not exist yet.

init-repo.sh DeSciX/egpt-frqtl --path <checkout> --token EGPT --community DeSciX/EGPT writes this from the template; --token and --community go together, and one without the other is refused. On a public or public-intended repo it runs in its public mode: it creates only the bounty and awarded labels, writes the bounty issue template and, with --token, the award policy, and refuses on stderr every coordination label, the decision and workstream templates and the roster. It deletes nothing: when the public repo already carries a coordination label it names each one and exits 1. On 2026-10-20 at 21:28 UTC DeSciX/egpt-frqtl carried no coordination label: its labels were bounty, awarded and GitHub's defaults, so init-repo.sh runs there in its public mode without that refusal. A public repo that does carry a coordination label has each one the refusal names deleted by its owner first (gh label delete <name> -R <owner/repo>, after moving any row that carries it to the private twin). Keep the policy in the private twin's checkout, where awarding is run. Publish it with publish.sh prepare award-policy --paths .beast/award-policy.md … so that contributors can read the policy each bounty cites.

Which repos may award the token

The community decides. Its repo, the one each policy names on its Community: line, commits .beast/awarders.json on its default branch. For EGPT that repo is DeSciX/EGPT, and its file, read 2026-10-20, is:

{"token": "EGPT", "awarders": ["DeSciX/EGPT", "DeSciX/egpt-frqtl", "DeSciX/egpt-godsworld", "DeSciX/egpt-lean"]}

The file has exactly the keys token and awarders (a non-empty list of owner/repo, each once, compared case-insensitively), and it is read through GitHub, never from a local copy. award.sh and bounty.sh refuse a repo the file does not list, naming the community repo and the missing entry (refused: <repo> may not award EGPT. The community repo DeSciX/EGPT lists the repos that may award EGPT in .beast/awarders.json (…)). A community repo without the file refuses every award and bounty of its token. A public ledger checks the same list for every repo in --repos. To let another repo award EGPT, the owner of DeSciX/EGPT adds it to awarders; that repo's own policy cannot grant it.

Post a bounty

${CLAUDE_PLUGIN_ROOT}/scripts/bounty.sh --repo DeSciX/egpt-frqtl --title "Three.js orbit controls in STUDIO" --amount 500 --token EGPT \
  --what "Orbit and pan controls for the STUDIO 3D view, using Three.js OrbitControls. Accepted means: merged, with a short demo in the PR."

This creates an issue titled Bounty: Three.js orbit controls in STUDIO with the label bounty and the sections Bounty, What, How to submit and Decides. Bounties are allowed on a public repo: unlike decisions and status, they are not coordination writes.

Award

${CLAUDE_PLUGIN_ROOT}/scripts/award.sh DeSciX/egpt-frqtl#57 --amount 500 --token EGPT --to @carol-dev \
  --for "accepted orbit controls (PR #57)" --ref https://github.com/DeSciX/egpt-frqtl/issues/51

This posts exactly one comment and adds the awarded label:

BEAST-AWARD amount=500 token=EGPT to=@carol-dev for="accepted orbit controls (PR #57)" ref=https://github.com/DeSciX/egpt-frqtl/issues/51

It refuses when any of these holds:

  • Your role on the repo is not admin or maintain.
  • The amount is not a plain decimal such as 500 or 12.5 (no thousands separator, no sign, no leading or trailing zero).
  • The token is not 2–12 upper-case letters or digits.
  • The recipient is not a GitHub login.
  • --for contains a double quote.
  • The policy is missing, names another repo or another token, or has no Community: line.
  • The community repo's .beast/awarders.json is missing or does not list the repo.

The moderator agent can draft a suggested amount as a MODERATOR-DRAFT comment, but it never awards, merges or labels awarded.

Monthly ledger

${CLAUDE_PLUGIN_ROOT}/scripts/ledger.sh --community EGPT --repos DeSciX/egpt-frqtl,DeSciX/egpt-godsworld --month 2026-11 --out ~/code/EGPT/awards
git -C ~/code/EGPT add awards/2026-11.jsonl awards/2026-11.md && git -C ~/code/EGPT commit -m "Awards 2026-11"

It reads every awarded issue and PR in the listed repos and keeps a BEAST-AWARD comment only when all four of these hold:

  • The comment parses.
  • Its token equals --community.
  • It was made in that month (UTC).
  • Its author is an admin or maintainer of that repo, checked live.

Each dropped comment is printed as DROPPED <url>: <reason>, and the run exits 2. A ledger with holes is never published by accident. Never edit the files by hand: award and regenerate.

Two checks stop the run instead of dropping anything:

  • A public ledger lists only public repos the community lists. When --out is inside a checkout of a public or public-intended repo (here DeSciX/EGPT), every repo in --repos must be public or public-intended too, and listed in that repo's .beast/awarders.json for --community. Either failure is refused, naming the repo, before anything is read (refused: --out … is in a checkout of …, and --repos names private repos: …). A private repo's awards stay in a private ledger, with --out in the private repo's own checkout.
  • The role read needs push access. GitHub answers a role query only to a login with push access on the repo. When the read fails (a 403), the run stops with exit 1 before writing any ledger file, naming the repo, the login and GitHub's answer (cannot read the role of <login> on <repo>: … (a 403 means the gh login lacks push access …)), and no award is dropped for it. Measured 2026-10-20: gh api repos/mrdoob/three.js/collaborators/mrdoob/permission → HTTP 403: Must have push access to view collaborator permission. So the community owner runs the ledger with a login that has push access on every listed repo.

The .jsonl rows (repo, item, to, token, amount, for, ref, by, at) are the machine-readable ledger. The .md file is the human-readable list.

From ledger to offer

The path from an award to tokens is ledger → sheet → the platform's Offers import → acceptance in Powch → settle. Since daita-beast 1.6.3, ledger.sh … --sheet <out.csv> --emails <map.csv> writes the month's award rows, the same rows as the .jsonl, as the CSV the DeSciX Offers import reads: the header contactemail,token,new_amount,batch,wallet_address and one row per award, with new_amount a plain decimal, batch awards-<YYYY-MM> unless --batch names another, and wallet_address left blank. The community owner uploads it to the Offers import; each recipient accepts the offer in Powch, which binds their wallet, and the airdrop settles. The login→email mapping is the platform's data, not Beast's: the owner supplies it as a file (header login,email, one <login>,<email> per line), and an awarded login missing from it refuses the whole run, naming the login, with nothing written. The sheet carries email addresses, so it must be written outside every git checkout.

4. Worked example: Three.js, egpt-frqtl STUDIO and Maxi's scenes

Hypothetical. Real: mrdoob/three.js (public, owned by the personal account mrdoob), DeSciX/egpt-frqtl, DeSciX/egpt-godsworld and the community repo DeSciX/EGPT (all public). Invented: carol-dev, an outside developer. How the Three.js maintainers set up seats and a private twin is in Setting up Beast, section 6.

(c) Where public developers send PRs

WorkSend the PR toWhat happens next
A new STUDIO capabilityDeSciX/egpt-frqtlA maintainer merges in GitHub. The project's private twin pulls it in with publish.sh pull before its next publish.
A new scene for MaxiDeSciX/egpt-godsworldSame pattern, through egpt-godsworld's own twin.
A change to the Three.js library itselfmrdoob/three.jsThree.js's own review process. Beast adds nothing on that repo unless its owner keeps an award policy for it and the community lists it.

(d) How each of them earns tokens

  • Carol, an outside developer, on egpt-frqtl or egpt-godsworld: she follows section 2. The award is in EGPT, posted by an admin or maintainer of that DeSciX repo, and appears in DeSciX/EGPT's awards/2026-11.md.
  • A Three.js maintainer contributing to egpt-frqtl: the same as Carol. A PR that lands on the public repo is awarded there. Work done only inside the private twin is not on the bulletin board: a ledger written into the public community repo refuses the twin in --repos, so award the public PR or the publish that the work produced.
  • A Three.js maintainer awarding others on egpt-frqtl: only with the maintain or admin role on DeSciX/egpt-frqtl, which a DeSciX organization admin must grant (Gap 2).
  • A contributor to mrdoob/three.js: an EGPT award there needs three things. The owner of DeSciX/EGPT adds mrdoob/three.js to awarders; the repo's owner keeps a policy for it (Token: EGPT, Community: DeSciX/EGPT); and an admin of mrdoob/three.js runs award.sh (Gap 2). The community ledger then lists mrdoob/three.js in --repos, run by a login with push access there.

One award policy per repo, by design. The policy is read from the root of the checkout you run in and names exactly one repo (plugin/scripts/lib.sh:1241-1243). Each repo that awards keeps its own policy, so awarding on DeSciX/egpt-frqtl and on DeSciX/egpt-godsworld runs from each one's own private twin.

Gaps: what the hypothetical needs and 1.5.11 does not do

  1. Beast records awards; the platform pays them. The ledger's sheet is the input of the DeSciX Offers import (From ledger to offer); Beast itself touches no chain.
  2. Awarding needs a role on the repo the comment lands on. award.sh refuses unless the caller's role is admin or maintain (plugin/scripts/award.sh:34-36). Three.js maintainers cannot award on DeSciX/* repos without a grant, and DeSciX cannot award on mrdoob/three.js. GitHub's documented permission levels give a personal account's repo only an owner and write collaborators, with no maintain role, so on mrdoob/three.js only mrdoob could award. That last point comes from GitHub's documentation and was not measured here.
  3. Another organization's token has no DeSciX home. award.sh accepts any 2–12 character symbol (plugin/scripts/award.sh:27), so with its own community repo and .beast/awarders.json a THREE ledger can be generated. The rule is "community id == token symbol", though (plugin/skills/award/SKILL.md:15), and no DeSciX community exists for it, so nothing would import it.
  4. Beast has no claim step for contributors. The login→email mapping the sheet needs is the platform's data, supplied by the community owner as a file, and the wallet binds when the recipient accepts the offer in Powch (From ledger to offer).
  5. The public app repos carry no award policy or bounty template yet. On 2026-10-20 at 21:28 UTC DeSciX/egpt-frqtl returned 404 for .beast and .github and had no bounty issues, so award.sh there has no policy to read. DeSciX/EGPT carries .beast/awarders.json (above) and no awards/ directory yet. Every bounty body says "see .beast/award-policy.md" (plugin/scripts/bounty.sh:32), a file contributors cannot read until it is published.
